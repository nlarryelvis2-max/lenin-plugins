# Changelog

## Lenin Owner 0.9.1

- Встроенный Owner MCP веб-чата принимает короткоживущую browser session
  текущего владельца через закрытый loopback платформы и больше не требует
  отдельного `/lenin-owner:connect` внутри Web.
- Session cookie имеет приоритет над любым локальным owner token, никогда не
  отправляется во внешний URL и не следует redirect; пустая, повреждённая или
  истёкшая web-сессия завершается понятной просьбой обновить страницу.
- Терминальный Owner MCP сохраняет прежний Bearer-контракт и отдельное
  одноразовое подключение.

## Lenin Owner 0.9.0

- Добавлен единый подтверждаемый сценарий создания компании с её первым
  проектом: owner назначается сразу, а проект получает точный `company id`,
  фактически возвращённый платформой.
- Обычное создание компании теперь явно сообщает, что без `owner_login`
  владельцем становится подключённый global owner.
- Если создание первого проекта завершилось ошибкой, пустая компания
  архивируется и MCP возвращает явный результат компенсации вместо тихого
  частичного успеха.

## Lenin Owner 0.8.0

- Добавлена единая двухфазная отправка сообщений: сначала полный preview,
  затем публикация только по короткоживущему одноразовому confirmation token.
- В preview явно фиксируются проект, видимый автор (`owner` или `lenin`),
  адресат (`team` или конкретный участник), командная видимость и точный текст.
- Адресное сообщение участнику публикуется как `@упоминание` в командном чате
  проекта и не выдаётся за приватный direct message.
- Текст от имени Ленина помечается как заданный владельцем; повтор подтверждённой
  отправки идемпотентно возвращает тот же receipt.

## Lenin Owner 0.7.0

- Добавлены portfolio/project digest с общими документами, материалами,
  обязательствами, уточнениями, heartbeat/autopilot receipts и статусами
  интеграций без выдачи private project files.
- `project_delegate` запускает обычный проектный turn Ленина с существующим
  Project MCP и возвращает durable message/trace receipt; повтор с тем же
  `operation_id` восстанавливает результат без второго запуска.
- Добавлены project archive/restore, приглашения, гостевые ссылки, user
  archive/restore aliases и редактирование иконок.
- Read-запросы и идемпотентные delegate-запросы получили bounded retries;
  обычные mutations автоматически не повторяются.
- Добавлен live capabilities handshake для проверки совместимости платформы и
  Owner MCP.

## Lenin Owner 0.6.1

- Исправлена регрессия `0.6.0`: Owner MCP снова создаёт и обновляет дочерние
  project workspaces через `parent_project_id`, `inherit_members` и
  `inherit_materials`, сохраняя новые company-tools.

## Lenin Owner 0.6.0

- Добавлены отдельные owner-инструменты для списков и карточек компаний и
  проектов, состава компаний, ролей участников и приглашений.
- Owner-контракт различает company boundary и project workspace; корневой и
  дочерний проект инспектируются одним набором tools, а parent и направленное
  наследование передаются явными полями проекта.
- Чтение командных чатов остаётся ограниченным глобальным owner scope,
  обязательной причиной и audit-записью; публикация и изменения доступов
  требуют `confirmed=true`.

## Lenin Owner 0.5.0

- Добавлен контракт иерархии project workspaces внутри компании.

## Lenin Owner 0.2.0

- Добавлены фильтруемый user list и карточка аккаунта с логином, ролью,
  статусом, проектными grants, наличием пароля и состоянием Uplink.
- Добавлены owner-команды для чтения личного контекста, project-scoped истории
  переписки и агрегированного Uplink inventory с обязательной причиной аудита.
- Добавлены подтверждаемые сброс временного пароля и включение/отключение
  аккаунта. Существующие пароли, raw Uplink paths и тексты сессий не выдаются.
- Owner-код и scope `owner:admin` ограничены глобальной ролью `owner`; обычная
  роль `admin` не может подключить или использовать owner MCP.

## Lenin Client 0.2.0 · Core 0.1.5 · Uplink 1.1.4

- Добавлен отдельно устанавливаемый `lenin-owner` MCP со scope `owner:admin`;
  обычный `lenin-client` больше не загружает административные инструменты.
- Владелец может просматривать реестр, создавать participant-аккаунты без
  проектов и выдавать или отзывать проектные доступы.
- Пакетный bootstrap сохраняет временные пароли в локальный TSV с mode `0600`,
  не сбрасывая существующие аккаунты.

## Lenin Client 0.1.1 · Core 0.1.5 · Uplink 1.1.4

- Синхронизация выключена до явного подключения одноразовым кодом.
- Добавлена команда `/lenin-client:uplink disconnect` для отзыва доступа Mac.
- При недоступной платформе локальная отправка останавливается, а token
  сохраняется для повторной попытки серверного отзыва.
- Пользовательские подсказки синхронизированы с постоянным разделом платформы
  **Установить Ленина**.

## Lenin Client 0.1.0 · Core 0.1.5 · Uplink 1.1.3

- Добавлен единый публичный пакет `lenin-client` без дублирования core/uplink.
- Регистрация согласована с приватной платформой через одноразовый setup-код.
- Token сохраняется локально с mode `0600` и не выводится.
- После регистрации отправляется безопасный heartbeat без сырых сессий.
- Heartbeat сообщает структурированные версии Client/Core/Uplink.
- Сохранены hardening-правки путей, атомарной записи, log rotation и защита от
  исчезновения активного session-файла между scan и read.
- Сохранена совместимость с отдельными компонентами `lenin-core` и
  `lenin-uplink`.
